# Personal Budget Tracker (MP101 Intermediate Lab), Firebase version

Flutter app for managing income, expenses, monthly budget, category limits, savings goal, recurring expenses and analytics. Data is stored in **Cloud Firestore** with **offline persistence** turned on, so the app keeps working without internet and syncs when the connection returns.

## Setup

### 1. Flutter project
1. `flutter create personal_budget_tracker`
2. Copy `lib/`, `test/`, `pubspec.yaml` and `firestore.rules` from this folder into the new project, replacing the existing ones.
3. `flutter pub get`

### 2. Firebase project (console.firebase.google.com)
1. Create a project (Google Analytics is optional).
2. **Build > Firestore Database > Create database.** Pick a region close to you (for example `asia-southeast1`) and start in production mode.
3. Open the **Rules** tab, paste the contents of `firestore.rules`, then click **Publish**.
4. **Build > Authentication > Get started > Sign-in method > Anonymous > Enable.**

### 3. Connect the app
```
npm install -g firebase-tools
firebase login
dart pub global activate flutterfire_cli
flutterfire configure
```
Run `flutterfire configure` inside the project folder and select your project and Android. It creates `lib/firebase_options.dart`. **The app will not compile without this file.**

### 4. Android minimum SDK
In `android/app/build.gradle` (or `build.gradle.kts`), set `minSdk = 23`. Cloud Firestore requires it.

### 5. Run
`flutter run` on an emulator or phone. **The first launch must be online** so the anonymous account can be created. After that, the app works offline, even after a restart.

Tip: Settings (gear icon) > **Load sample data** fills the app with numbers that match the activity sheet (budget ₱25,000, income ₱25,000, expenses ₱17,450, last month ₱15,200). Useful for screenshots.

## How it works (for the oral explanation)

**Data layout.** Each user gets their own space: `users/{uid}/incomes`, `expenses`, `budgets`, `category_budgets`, `savings_goals`, `recurring_expenses`. The uid comes from Firebase Anonymous Auth. The security rules only let a user read and write their own data, and reject amounts of zero or below.

**Data flow.** Screen → `AppState` → `DatabaseService` → Firestore. `AppState` subscribes to Firestore snapshot streams for the selected month. When anything changes, Firestore pushes the new data, `AppState` calls `notifyListeners()`, and every screen (wrapped in `ListenableBuilder`) rebuilds. No total is stored or hard-coded; they are all computed from the records.

**Offline.** `Settings(persistenceEnabled: true)` keeps a local copy of the data on the device. Offline, reads come from that cache and writes are saved locally and queued. When the phone reconnects, Firestore syncs them to the cloud automatically. Writes are not awaited on purpose: offline, the Future only completes after the server confirms, which would freeze the save button.

**Why batches instead of transactions.** "Mark as paid" saves an expense and moves the recurring due date together using a `WriteBatch`. Firestore transactions require internet, batches work offline.

**Search and filter.** Firestore cannot do "contains" text search. The app queries the date range from Firestore, then applies the search text, category, payment method and amount range in Dart (`ExpenseFilter.matches`). This avoids needing composite indexes.

**Formulas** (`finance_calculator.dart`):
- Remaining Budget = Monthly Budget - Total Expenses
- Budget Used = Total Expenses / Monthly Budget × 100
- Percentage Used (category) = Category Expenses / Category Budget × 100. Below 80% normal, 80 to 99% warning, 100% and up exceeded
- Savings Progress = Current Savings / Savings Target × 100
- Savings Rate = Savings / Total Income × 100
- Remaining Balance (Analytics) = Total Income - Total Expenses
- Average Daily Spending = Total Expenses / days. Current month uses days elapsed so far; past months use the full number of days
- Monthly comparison = This month's expenses - Last month's expenses

**Design decisions.**
- Monthly budget is saved per month. If a month has none, the latest earlier budget is carried over (shown on screen).
- Category limits are standing limits that apply every month.
- Savings goal is per month.
- Recurring expenses have their own collection, separate from ordinary transactions.

## Demo checklist

1. Dashboard shows all six values for the month.
2. Add, edit (tap) and delete (long press or trash icon) income and expenses.
3. Try saving an expense with amount 0, -500, empty title, no category: each shows an error and nothing is saved.
4. Add a Shopping expense past its limit: the "budget exceeded" alert appears.
5. Expenses tab: search, then filter by category, payment method, date range and amount range. Show the "No matching expenses" state.
6. Recurring tab: mark a payment as paid, then show the new expense and the moved due date.
7. Analytics: all six metrics plus the monthly comparison.
8. Persistence: add an expense, close the app fully, reopen. The expense is still there.
9. Offline: turn on airplane mode and repeat steps 2 to 8. Turn internet back on and show the data appearing in the Firebase console.

Screenshots needed: Dashboard, Expenses, Budget, Analytics.

Run the formula tests with `flutter test`.
